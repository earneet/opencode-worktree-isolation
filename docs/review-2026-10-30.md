## 2. 最终缺陷清单（对抗验证后）

### P0-1【中】strictGitOps 缺陷群（5 项收敛，历史根因：v0.4.0 借用计划）

- **保护集无 master/main 硬编码**：`lib.ts:911-915` 仅消费 `cfg.protectedBranches`（默认 `[]`）。默认配置下 master 上 `git merge`/绑定中 `git checkout master`/裸 `git push` 全放行。README:184 "hardcoded safety net" 承诺落空。唯一硬编码是 `:786` push 显式点名正则。
- **push 绕过**：`git push origin` / `git push -f` / `git push -u origin` 均绕过（`GIT_PUSH_DEFAULT_RE` 首尾锚定只匹配裸命令；显式正则只认 master/main 字面量，不认 protectedBranches 中的其他分支）。
- **branch 绕过**：`git branch -f master HEAD`（强移保护分支指针）、`git branch --delete x`、`git branch -df x` 均不被 `GIT_DEL_BRANCH_RE`（仅 `-[dD]` 后跟空白）覆盖。
- **checkout/switch 绕过**：`git switch -C master`、`git checkout -B master` 因捕获组首字符排除 `-` 而绕过。
- **branchCache 陈旧**（合并 A2）：`lib.ts:839-847` 进程级永久缓存分支名，主检出切分支后基于陈旧分支判定（前提：目标分支 ∈ protectedBranches）。
- **测试掩盖**：`unit.test.js:843` 显式传 `new Set(["master","main"])`，永远测不到默认配置；`lifecycle.test.js:1217` sidecar 显式配置。`core.ts:833` 提示文案集合为空时回退显示 "master, main" 掩盖缺口（文案源自借用计划 `:979` 原文）。
- **历史根因**：`.omo/plans/worktree-borrow-zcode.md:606-644` 与实现逐字一致（含无硬编码的集合构造）；计划自带验收清单 `:688-694`（"git push (default, on master) → deny" 等）若按默认配置实现本可当场暴露缺口，实际测试按实现而非意图编写。

### P0-2【中·仅 Windows】尾部点/空格绕过 `.git` 防护

`isDotGitPath`（`lib.ts:194-197`）字面匹配 `/.git/` 段；`R\.git.\hooks` 物理等价 `R\.git\hooks`（Win32 剥离每段尾部点/空格）但不命中拦截。默认配置一步可达植入 git 钩子；`worktree_allow(add, ".git./**")` 组合链全程走通；glob/grep 的 `.git` 检查同构可绕。击穿插件唯一常开文件防线（design.md §7 无条件设计目标）。`isDotGitPath` 段匹配本身是 issue #6 修复产物，本项是其下一轮硬化。

## 4. 历史结论

项目为 issue 驱动开发（#1/#2/#5-#12 均为 fix+测试+design.md 增补，测试从 51 增至 290）。**所有已确认缺陷集中在从未被 issue 触达的区域**：被 issue 打过的区域（路径规范化 #6/#8/#10、僵尸绑定 #7、静默重写 #11）经三轮对抗审查零证伪；strictGitOps 正则/保护集/branchCache/尾部点/状态并发是 v0.4.0 一次性移植后未被二次审视的部分。
